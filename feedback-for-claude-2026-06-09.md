## Что исправить в логике разбора

### 1. Дата в имени файла — из транскрипта, не из текущего дня

Когда переносишь файл из `/emmbase/inbox/` в карточку клиента:

- **Источник даты события**: метаданные внутри inbox-файла (например `# Дата:` в YAML-разметке) или дата в имени transcript-файла (формат `ГГГГ-ММ-ДД_voice-...md` — это дата звонка, не дата разбора).
- **НЕ использовать** `datetime.today()` или `date.today()` — это дата **разбора inbox** Claude'ом, не дата события.

Пример правильного парсинга для voice-файлов от cron-watcher:
- Имя файла в inbox: `2026-06-09_0937_voice-8_499_391-92-88_20260609093726-...md`
- Заголовок в YAML: `# Дата: 2026-06-09 09:37`
- → итоговое имя в карточке: `2026-06-09_транскрипт-звонок.md` (не `2026-06-08`)

Для PBX-формата исходного файла `8_499_391-92-88_20260609093726---uuid.amr`:
- Подстрока `20260609093726` = `YYYYMMDDHHMMSS` — это **дата+время звонка**. Парсить так:
  ```python
  ts = re.search(r"_(\d{14})---", original_name).group(1)
  date_str = f"{ts[:4]}-{ts[4:6]}-{ts[6:8]}"
  ```

### 2. Защита от перезаписи существующих файлов в карточке клиента

Если в `КЛИЕНТЫ/<имя>/` уже есть файл с тем же именем (`2026-06-09_транскрипт-звонок.md`) — **не перезаписывать**. Варианты:

- Если содержимое идентично → пропустить (это повторный разбор того же файла).
- Если другое → новый файл с суффиксом по времени: `2026-06-09_транскрипт-звонок_1437.md` (HHMM из метаданных).
- Альтернативно — собрать оба в один файл с разделителем `---` и обоими timestamp'ами.

**Никогда не делать silent overwrite** в карточках клиентов. Это потеря данных.

### 3. Лог решений в DECISIONS_LOG.md

После каждого разбора inbox добавлять запись в `~/emmbase/DECISIONS_LOG.md`:

```markdown
## 2026-06-09 (Claude inbox triage)

- Перенесено `inbox/2026-06-09_voice-Бакланов....md` (29.7 KB транскрипт) → `КЛИЕНТЫ/Альфарма-М (Баканов)/2026-06-09_транскрипт-звонок.md`. Звонок 09.06 09:37 МСК, длительность 23 мин.
- ...
```

Это позволит Руслану и боту легко проверить «куда делся файл X» через grep.

### 4. Хранение оригинала inbox-файла в _archive

После переноса инструкции/транскрипта из inbox в карточку клиента — оригинал из `/emmbase/inbox/<имя>.md` **перемещать в `/emmbase/inbox/_archive/<имя>.md`**, а не удалять. На случай если потребуется откатить разбор или сверить с источником.

### 5. Уведомление Руслану в Telegram при разборе

Опционально (можно через bot-script): после разбора inbox послать Руслану коротко в Telegram:

```
🗂 Inbox разобран (N файлов):
✓ Бакланов звонок 23 мин → Альфарма-М/2026-06-09_транскрипт-звонок.md
✓ ... (другие)
```

Тогда Руслан сразу видит куда что попало и не теряет файлы.

### 6. Если файл голосовое + есть `Не использовать` соответствие — спросить, не просто перезаписать

Когда видишь голосовое транскрипт по номеру телефона:
- Найти карточку клиента по этому номеру (поиск по `КЛИЕНТЫ/*/index.md` или telephone metadata).
- Если найдено → перенести.
- Если **не найдено** (новый номер) → оставить в `/emmbase/inbox/_pending-clients/` с типом «новый клиент?» — Руслан сам решит куда привязать. Не выдумывай.
